Popup Store Atlas

흩어져 있는 팝업스토어 소식을 여러 웹 출처에서 모아 정리하고, 위치 정보와 함께 데이터베이스에 넣어 지도에서 보여 주는 프로젝트입니다. 수집, 정제, 적재, API, 화면까지 한 저장소에서 다뤘습니다.

  • GitHub 저장소

해결하려는 문제

팝업스토어 정보는 백화점 공지, 잡지 기사, 개인 블로그에 형식도 제각각으로 흩어져 있습니다. 이름, 주소, 기간이 빠지거나 표기가 다르고, 같은 행사가 여러 곳에 중복으로 올라옵니다. 이걸 한곳에 모으고, 지금 열려 있는 곳만 지도에서 볼 수 있게 하는 게 목표였습니다.

주요 시도

  1. 출처마다 다른 형식을 어댑터로 분리

    현대백화점, 마리끌레르, 티스토리 블로그 세 출처를 각각 어댑터로 나누고, 뽑아낸 후보를 같은 정제 파이프라인으로 보냈습니다. 출처가 늘어도 어댑터 하나만 추가하면 되는 구조입니다.

  2. 버린 데이터도 이유와 함께 남기기

    이름, 주소, 기간이 없거나 허용 지역(서울, 경기 등)이 아니거나 허용 도메인의 https 주소가 아니면 버리되, 이유를 붙여 거부 목록에 따로 저장했습니다. 지오코딩에 실패한 주소도 별도 목록으로 남겨서, 수집 규칙을 고칠 때 근거로 썼습니다.

  3. 중복 없이 적재하고 위치로 조회

    카카오 로컬 API로 주소를 좌표로 바꾸고, 행마다 중복 키를 만들어 같은 행사는 한 번만 들어가게 했습니다(ON CONFLICT DO NOTHING). PostGIS 좌표 컬럼에 GiST 인덱스를, 기간 컬럼에 인덱스를 두어 지금 열린 팝업을 빠르게 조회합니다.

보안 설정

공개 API와 남의 사이트를 읽는 크롤러가 함께 있는 프로젝트라, 기능을 만든 뒤 보안 설정을 따로 한 번 정리했습니다.

  • 크롤러는 허용한 도메인의 https 주소만 읽습니다.
  • API에 클라이언트별 슬라이딩 윈도우 rate limit을 직접 구현해 적용했습니다. 초과하면 429와 Retry-After를 돌려줍니다.
  • 응답에 보안 헤더를 붙이고, API 문서(/docs)는 기본으로 꺼 둡니다.
  • 카카오 API 키는 명령줄 인자로 넘기지 않고 환경변수로만 받습니다.

트러블슈팅

  • 무료 플랜에서 배포 전 DB 초기화가 안 됨

    Render 무료 플랜은 배포 전 명령(pre-deploy command)을 지원하지 않아 PostGIS 확장과 테이블을 자동으로 만들 수 없었습니다. 배포 설정에서 빼고, 서비스가 생성된 뒤 로컬에서 초기화 스크립트를 한 번 실행하는 절차로 바꿔 README에 남겼습니다.

  • API가 잠들면 지도가 비어 보임

    무료 서버가 쉬고 있을 때 첫 요청이 실패하면 화면이 통째로 비었습니다. 내장 카탈로그를 두고, API 응답이 없으면 기준 날짜를 표시한 채 그 데이터로 대신 보여 주도록 했습니다.

  • 블로그마다 주소와 이름 표기가 다름

    같은 장소를 다른 이름이나 줄임말로 쓴 글이 많아 주소를 놓쳤습니다. 주소 힌트 사전과 추출 규칙을 늘리고, 실제 블로그 글을 본뜬 테스트 HTML로 확인했습니다.

한계와 다음 작업

  • 수집 건수, 정제 후 남는 비율, 응답 속도 같은 수치는 기록해 두지 않았습니다. 다시 돌려서 측정할 계획입니다.
  • 크롤링은 수동 실행입니다. 정기 실행과 실패 알림은 아직 없습니다.
  • rate limit은 프로세스 메모리에 있어 서버를 여러 대로 늘리면 공유되지 않습니다.
