Popup Store Atlas

팝업스토어의 위치와 운영 기간을 여러 사이트에서 따로 찾는 불편을 줄이기 위해 개발했습니다. 출처별 정보를 수집·정제하고 PostGIS에 적재한 뒤, 진행 중인 행사를 지도에서 조회하도록 구현했습니다.

  • 라이브 사이트
  • GitHub 저장소

해결하려는 문제

백화점 공지·잡지 기사·블로그마다 정보 형식이 달랐고, 이름·주소·기간이 빠지거나 같은 행사가 중복되는 문제가 있었습니다. 방문 전에 진행 중인 행사와 위치를 함께 확인할 수 있도록, 수집부터 지도 조회까지 연결하는 것을 목표로 잡았습니다.

주요 시도

  1. 출처마다 다른 형식을 어댑터로 분리

    현대백화점, 마리끌레르, 티스토리 블로그 세 출처를 각각 어댑터로 나누고, 뽑아낸 후보를 같은 정제 파이프라인으로 보냈습니다. 출처별 추출 규칙을 공통 정제 로직과 분리했습니다.

  2. 버린 데이터도 이유와 함께 남기기

    이름, 주소, 기간이 없거나 허용 지역(서울, 경기 등)이 아니거나 허용 도메인의 https 주소가 아니면 버리되, 이유를 붙여 거부 목록에 따로 저장했습니다. 지오코딩에 실패한 주소도 별도 목록으로 남겨서, 수집 규칙을 고칠 때 근거로 썼습니다.

  3. 중복 없이 적재하고 위치로 조회

    카카오 로컬 API로 주소를 좌표로 바꾸고, 행마다 중복 키를 만들어 같은 행사는 한 번만 들어가게 했습니다(ON CONFLICT DO NOTHING). PostGIS 좌표 컬럼에는 GiST 인덱스를, 기간 컬럼에는 별도 인덱스를 두고 진행 중인 팝업을 조회하도록 구현했습니다.

보안 설정

공개 API와 외부 웹 출처를 읽는 크롤러가 함께 있는 구성이어서 URL 수집 경계와 공개 API 설정을 점검했습니다.

  • 크롤러는 허용 도메인의 HTTPS 주소만 읽도록 제한했습니다.
  • API에 클라이언트별 슬라이딩 윈도우 rate limit을 직접 구현해 적용했습니다. 한도를 초과하면 429와 Retry-After를 반환하도록 구현했습니다.
  • 응답에 보안 헤더를 추가했고 API 문서(/docs)는 기본으로 비활성화했습니다.
  • 카카오 API 키는 환경변수로만 입력받도록 구성했습니다.

트러블슈팅

  • 무료 플랜에서 배포 전 DB 초기화가 안 됨

    Render 무료 플랜은 배포 전 명령(pre-deploy command)을 지원하지 않아 PostGIS 확장과 테이블을 자동으로 만들 수 없었습니다. 배포 설정에서 빼고, 서비스가 생성된 뒤 로컬에서 초기화 스크립트를 한 번 실행하는 절차로 바꿔 README에 남겼습니다.

  • API가 잠들면 지도가 비어 보임

    무료 서버가 쉬고 있을 때 첫 요청이 실패하면 화면이 통째로 비었습니다. 내장 카탈로그를 두고, API 응답이 없으면 기준 날짜를 표시한 채 그 데이터로 대신 보여 주도록 했습니다.

  • 블로그마다 주소와 이름 표기가 다름

    같은 장소를 다른 이름이나 줄임말로 쓴 글이 많아 주소를 놓쳤습니다. 주소 힌트 사전과 추출 규칙을 늘리고, 실제 블로그 글을 본뜬 테스트 HTML로 확인했습니다.

한계와 다음 작업

  • 수집 건수, 정제 후 남는 비율, 응답 속도 같은 수치는 기록해 두지 않았습니다. 다시 돌려서 측정할 계획입니다.
  • 수집은 수동 실행으로 구현했습니다. 정기 실행과 실패 알림은 아직 추가하지 않았습니다.
  • rate limit은 프로세스 메모리에서 처리했습니다. 여러 서버 간 공유는 구현하지 않았습니다.
